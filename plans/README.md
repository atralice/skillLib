## Findings considered and rejected

So that nobody audits them again without a new reason.

- **Git errors read as "not tracked"** (`src/library.ts:459`, `src/git.ts:26`):
  not planned. The code path is real: if `git` refuses the repo, skilllib can
  treat committed folders as new. No real trigger was confirmed. Needs a
  reproduction first (for example a "dubious ownership" checkout).
- **No lock between two skilllib runs** (`stash` in `src/library.ts:1233`,
  `writeManifest` in `src/project.ts:117`): not planned. Two agents at the
  same moment can lose a pin or a backup index entry. The fix (a lock file
  with expiry) is a design decision for the maintainer. Plan 002 part B covers the
  interrupted-run case only.
- **Content hashes depend on line endings** (`src/skills.ts:62`): not planned.
  A Windows checkout with `core.autocrlf=true` would show committed skills as
  edited. The fix changes every recorded hash and needs a migration design.
- **A personal change can rewrite a committed `skilllib.json`**
  (`src/project.ts:126`, `writeChanged` at `:140`): only when the file holds
  legacy or hand-edited entries (old string pins, `@owner/name`, unsorted
  pins). Low impact.
- **Skill names differ only by case on macOS and Windows**
  (`src/library.ts:446`, `:874`): `add Foo` with a library skill `foo` writes
  a pin `Foo`. Rare. A single name validator would also cover names such as
  `constructor`, which today read as "pinned" through the object prototype
  (`src/library.ts:1013`).
- **Windows runs a `git.exe` or `claude.exe` from the current folder first**:
  general Node behavior for a bare program name. Not verified on Windows.
- **Terminal control characters in skills.sh names and SKILL.md
  descriptions** (`src/commands.ts:1163`, `src/skills.ts:22`): low impact.
- **`tidy:global` is a safe fix and never checks git** (`src/health.ts:531`,
  `src/tidy.ts:268`): matters only when `~/.claude/skills` is itself inside a
  git repo. Low frequency.
- **Deferred, not rejected: `apply <id> <n>` picks by number from a list
  rebuilt at apply time** (`src/commands.ts:734`): labels are safe and the
  manual already says so. See the maintenance notes of plan 002 part A.
- **The "committed copy is the team's" rule is written in four places**
  (`src/commands.ts:362`, `src/here.ts:65`, `src/tui/load.ts:89`,
  `src/health.ts:1067`): real duplication, medium refactor risk, no user
  impact today.
- **No lint or format script**: `tsc` strict with `noUnusedLocals` covers
  most of it. A first format pass would touch every file.
- **`recordOrigin` in `installFound` overwrites a skill's first origin**
  (`src/install.ts:217`), and the usage cache has no parser version
  (`src/usage.ts:98`): both small; not planned.
- **Deferred, not rejected: repeated `git` process starts during a scan**
  (the `linkEverywhere` dry runs near `src/health.ts:968`, and
  `isGitTracked` at `src/library.ts:712`): wait for a measurement (plan 004).
